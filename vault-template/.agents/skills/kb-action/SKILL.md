# 行动卡点

<!-- KB-OWNED-WORKFLOW: v1 -->

## 开始前

1. 从当前目录向上找到 `.kb/config.yaml`，按配置解析六类资产库。
2. 只读取本任务需要的文件，不跨知识库搜索。
3. 把库内事实、用户本轮信息、当前推断和未知项分开。
4. 原始材料不覆盖；删除、移动和批量写入先确认。

## 读取

- 当前目标
- 已承诺动作
- 最近一次尝试
- 实际阻力
- 可用时间和资源

## 必须保留的能力

- 诊断知道但不行动的具体阻点
- 区分方向不清、条件不足、未承诺和回避结果
- 把任务缩成一个可完成动作
- 约定完成信号和回填时间

## 执行

1. 区分不知道做什么、做不到、未承诺和在回避结果。
2. 找出动作开始前的最后一个具体阻点。
3. 把任务改写为有对象、动作、完成信号和截止时间的一步。
4. 约定一次回填，不做长期激励演讲。

## 交付

- 卡点类型
- 下一步动作
- 完成信号
- 所需支持
- 回填时间

每个关键判断附来源路径；没有来源的内容标为推断或待确认。

## 写回

- 用户同意后把动作写入当前任务状态
- 完成结果回到相关项目记录

## 停止条件

- 目标本身不清时转 kb-goal
- 需要专业心理支持时不代替专业人员
- 不使用羞辱或人格判断

## 接续

- 目标不清用 kb-goal
- 方向不清用 kb-diagnose

来源沿革只用于追溯，不作为运行指令。需要追溯时读取 `references/source-map.md`。
