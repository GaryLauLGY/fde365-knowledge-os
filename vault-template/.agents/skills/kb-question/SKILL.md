# 问题说明

<!-- KB-OWNED-WORKFLOW: v1 -->

## 开始前

1. 从当前目录向上找到 `.kb/config.yaml`，按配置解析六类资产库。
2. 只读取本任务需要的文件，不跨知识库搜索。
3. 把库内事实、用户本轮信息、当前推断和未知项分开。
4. 原始材料不覆盖；删除、移动和批量写入先确认。

## 读取

- 原问题
- 已知事实
- 已尝试动作
- 期望决定
- 时间和权限边界

## 必须保留的能力

- 把模糊困惑改成问题说明书
- 让问题可推理、可批评和可验证
- 列出所缺事实和权限
- 判断可自动化、需人工判断和不可自动化的部分

## 执行

1. 逐句区分事实、判断、情绪和请求。
2. 找出答案会改变哪个决定。
3. 列出处理问题所缺的最少信息。
4. 把步骤分为可由 Agent 执行、需要人确认、必须由人决定三类。
5. 输出可推理、可批评、可验证的问题说明书和自动化边界。

## 交付

- 原问题
- 问题说明书
- 已知事实
- 缺失信息
- 期望输出
- 验收标准

每个关键判断附来源路径；没有来源的内容标为推断或待确认。

## 写回

- 确认后写入当前项目 brief

## 停止条件

- 没有决策用途时先问为什么处理
- 涉及授权外动作时停止
- 不把猜测写进背景事实

## 接续

- 商业问题用 kb-diagnose
- 目标问题用 kb-goal

来源沿革只用于追溯，不作为运行指令。需要追溯时读取 `references/source-map.md`。
