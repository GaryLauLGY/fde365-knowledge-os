# 套件更新

<!-- KB-OWNED-WORKFLOW: v1 -->

## 开始前

1. 从当前目录向上找到 `.kb/config.yaml`，按配置解析六类资产库。
2. 只读取本任务需要的文件，不跨知识库搜索。
3. 把库内事实、用户本轮信息、当前推断和未知项分开。
4. 原始材料不覆盖；删除、移动和批量写入先确认。

## 读取

- 当前 VERSION
- kb-manifest.json
- 配置中的 update_source
- 本地改动

## 必须保留的能力

- 检查当前和候选版本
- 只使用配置中的更新来源
- 展示新增、修改、删除和本地冲突
- 确认后只更新 kb-suite
- 不修改六类资产和状态

## 执行

1. 验证更新来源是用户配置的地址或目录。
2. 读取版本和清单，不直接覆盖。
3. 比较新增、修改、删除和本地改动。
4. 生成备份与更新预览，确认后执行并重新校验。

## 交付

- 当前版本
- 候选版本
- 差异
- 本地冲突
- 备份位置
- 验证结果

每个关键判断附来源路径；没有来源的内容标为推断或待确认。

## 写回

- 只更新 kb-* 和套件元数据
- 不修改六类资产和 `.kb/state`

## 停止条件

- 没有 update_source 时只报告
- 来源无法验证时停止
- 有本地改动时不强制覆盖

## 接续

- 更新后用 kb-health

来源沿革只用于追溯，不作为运行指令。需要追溯时读取 `references/source-map.md`。
