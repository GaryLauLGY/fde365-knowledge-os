# 生意诊断

<!-- KB-OWNED-WORKFLOW: v1 -->

## 开始前

1. 从当前目录向上找到 `.kb/config.yaml`，按配置解析六类资产库。
2. 只读取本任务需要的文件，不跨知识库搜索。
3. 把库内事实、用户本轮信息、当前推断和未知项分开。
4. 原始材料不覆盖；删除、移动和批量写入先确认。

## 读取

- 产品和价格
- 客户原话与成交记录
- 案例结果
- 交付方法
- 用户当前问题

## 必须保留的能力

- 支持单个问题问诊
- 支持完整业务体检
- 拆解客户、产品、证据、交付、获客和收入
- 找到最早失效环节
- 给出可观察的验证动作

## 执行

1. 把问题拆成客户、承诺、证据、交付、获客和收入六部分。
2. 为每部分列已知事实、矛盾和缺口。
3. 找出最早会让整条链失效的一处，不一次改所有环节。
4. 设计一个成本可控的验证动作，并写明通过和失败信号。

## 交付

- 一句话判断
- 证据表
- 最先处理的问题
- 验证动作
- 观察指标
- 暂不处理项

每个关键判断附来源路径；没有来源的内容标为推断或待确认。

## 写回

- 确认后的诊断写入方法库或 `.kb/state/decisions`
- 新客户事实回到客户库

## 停止条件

- 数据不足时不下结论
- 涉及法律、医疗或财务判断时要求专业核验
- 不把心理猜测当商业事实

## 接续

- 需要对标用 kb-benchmark
- 需要记录选择用 kb-decide

来源沿革只用于追溯，不作为运行指令。需要追溯时读取 `references/source-map.md`。
