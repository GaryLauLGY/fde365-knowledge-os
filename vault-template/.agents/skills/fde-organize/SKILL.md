# 资产整理

<!-- FDE-OWNED-WORKFLOW: v1 -->

## 开始前

1. 从当前目录向上找到 `.fde/config.yaml`，按配置解析六类资产库。
2. 只读取本任务需要的文件，不跨知识库搜索。
3. 把库内事实、用户本轮信息、当前推断和未知项分开。
4. 原始材料不覆盖；删除、移动和批量写入先确认。

## 读取

- 六类资产目录
- 文件名、标题、来源和修改时间
- 现有 `[[Wikilink]]`、反向链接和“关联资产”章节
- 用户现有命名规则
- `scripts/inventory_assets.py`
- references/unit-schema.md、topic-map-schema.md、assembly-schema.md

## 必须保留的能力

- 审计内容规模和处理边界
- 把长文拆成可复用内容单元
- 生成主题地图和关联
- 把确认的跨库关系写成两端真实 Obsidian 双链
- 从内容单元装配选题稿
- 处理重复、版本和来源

## 执行

1. 运行只读清单，确认内容规模、边界、重复和无来源文件。
2. 按 unit-schema 把长文拆成观点、问题、案例、方法和方案单元，每个单元保留来源。
3. 按 topic-map-schema 连接相关单元，记录支持、冲突、例子和版本关系。
4. 用户要求“整理关联”时，进入下方的跨库双链模式，不生成 Canvas 代替真实链接。
5. 按 assembly-schema 从单元装配选题稿，不复制旧文章。
6. 生成迁移和写入预览，需要批准时等待用户确认；确认后分批执行并记录日志。

## 跨库双链模式

1. 只建议有文件内容、来源或明确版本关系支持的跨库关联，不按标题相似度臆造关系。
2. 预览必须列出两端完整 Vault 相对路径、关系类型、依据和准备写入的链接文字。
3. 需要批准模式下，展示预览后等待用户确认；YOLO 模式下可以直接执行。
4. 写入时在两端 Markdown 笔记中创建或复用 `## 关联资产` 章节，并分别加入指向对方的 `[[完整/Vault/相对路径|标题]]`。两端都写，确保关系可见、可追溯。
5. 每条链接同时写明支持、冲突、例子或版本等关系类型和一句依据；保留正文，不重写原内容。
6. 写完后重新读取两端文件，并复查资产网络的跨库连接数量。
7. 除非用户明确要求，不创建 `.canvas`、Canvas 或 Canva 预览；它们不能替代 Markdown 双链。

## 交付

- 资产清单
- 内容单元
- 主题地图
- 跨库双链预览与写入记录
- 选题装配稿
- 迁移预览
- 执行日志

每个关键判断附来源路径；没有来源的内容标为推断或待确认。

## 写回

- 日志写入 `.fde/logs`
- 索引写入 `.fde/indexes`
- 已确认关系写入两端资产 Markdown 的 `## 关联资产`，使用完整 Vault 相对路径 Wikilink
- 原文件移动前保留可恢复记录

## 停止条件

- 不能确认真源时不合并
- 没有来源时不伪造
- 关系依据不足时不写双链
- 批量移动和覆盖必须确认

## 接续

- 整理后用 fde-health 复查
- 找资料用 fde-library

来源沿革只用于追溯，不作为运行指令。需要追溯时读取 `references/source-map.md`。
