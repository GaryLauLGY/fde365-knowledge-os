# 知识库体检

<!-- FDE-OWNED-WORKFLOW: v1 -->

## 开始前

1. 从当前目录向上找到 `.fde/config.yaml`，按配置解析六类资产库。
2. 只读取本任务需要的文件，不跨知识库搜索。
3. 把库内事实、用户本轮信息、当前推断和未知项分开。
4. 原始材料不覆盖；删除、移动和批量写入先确认。

## 读取

- `.fde/config.yaml`
- 六类资产路径
- 收件箱和内容阶段
- `.fde` 运行目录
- AGENTS.md、CLAUDE.md 和已安装 fde-* 清单

`.fde/config.yaml` 是唯一运行真源。旧 `.kb/` 只作历史追溯：不要读取其中配置来决定路径，也不要仅因它仍存在就报告真源冲突。

## 必须保留的能力

- 核对知识库配置与实际目录
- 核对 Agent 规则文件、Skill 和项目状态
- 发现路径、数据、版本和状态冲突
- 先报告，确认后再修正

## 执行

1. 验证配置字段、路径边界和目录可读性。
2. 统计六类资产的文件数、来源覆盖和最近更新。
3. 对照 AGENTS.md、CLAUDE.md、Skill 目录和实际项目状态，找路径、版本、数字和状态冲突。
4. 检查待处理材料、重复入库、内容阶段冲突和运行文件越界。
5. 把问题分为阻塞、要处理和提醒，只给出有证据的问题。

### 待处理口径

- 待处理数量只统计收件箱中的原始材料记录：兼容 `type: inbox` 或没有 `type` 的旧材料，但必须排除 README、`原始文件/`、`附件/`、分流预览、分流记录和处理记录。
- `status` 为 `processed`、`completed`、`closed`、`done`、`已完成`、`已处理` 或 `结案` 的原始材料属于已处理，不得再次计入积压或建议重新入库。
- 同源处理记录或正式资产可以作为终态证据；若原材料状态仍是 pending，报告“状态待对齐”，不要把同一材料同时统计为待处理和已处理。
- 同一材料有多份预览时，旧的 `awaiting-confirmation` 是历史审计记录；已有更新的 `confirmed-noop`、processed 收件记录或完成写入证据时，不把旧预览当成当前冲突，也不改写或删除它。
- 目录中的非隐藏文件总数不是待处理数量。报告时分别给出原始材料、有效待处理、已处理和派生产物数量。

## 交付

- 能否使用
- 问题路径和证据
- 影响
- 建议动作
- 等待确认的修正

每个关键判断附来源路径；没有来源的内容标为推断或待确认。

## 写回

- 默认不写；确认后只创建缺失空目录或修正明确的路径
- 修正规则真源时只更新 FDE365 管理的旧默认路径，不删除 `.kb/`，不覆盖自定义业务路径

## 停止条件

- 配置不存在时停止并询问根目录
- 业务事实冲突时不自动选边
- 不把空库当成损坏

## 接续

- 空库用 fde-interview
- 积压材料用 fde-ingest

来源沿革只用于追溯，不作为运行指令。需要追溯时读取 `references/source-map.md`。
