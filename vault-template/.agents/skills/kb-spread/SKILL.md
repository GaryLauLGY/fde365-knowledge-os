# 传播复盘

<!-- KB-OWNED-WORKFLOW: v1 -->

## 开始前

1. 从当前目录向上找到 `.kb/config.yaml`，按配置解析六类资产库。
2. 只读取本任务需要的文件，不跨知识库搜索。
3. 把库内事实、用户本轮信息、当前推断和未知项分开。
4. 原始材料不覆盖；删除、移动和批量写入先确认。

## 读取

- 原内容
- 平台数据
- 评论和转发语
- 发布时间和分发方式
- 同账号基线

## 必须保留的能力

- 没有发布数据时做内容机制假设
- 有数据时用评论和指标验证
- 分析受众情绪、有效立场和传播动作
- 给出可继续讨论的方向
- 区分相关性和因果

## 执行

1. 先判断是内容假设模式还是数据复盘模式。
2. 没有数据时，从身份表达、情绪释放、实用交换、群体信号和行动成本提出可证伪假设。
3. 有数据时确认口径和基线，拆分曝光、停留、互动、转发和转化信号。
4. 用评论原话验证受众情绪和有效立场，不替读者发明动机。
5. 输出可继续讨论的方向、反证和下一次实验。

## 交付

- 数据摘要
- 有效信号
- 可能机制
- 反证
- 下一次实验

每个关键判断附来源路径；没有来源的内容标为推断或待确认。

## 写回

- 写入内容库的 `数据复盘`，关联原发布稿

## 停止条件

- 没有数据时只做内容假设
- 平台口径不同不直接横比
- 相关性不写成因果

- 下一稿用 kb-write
