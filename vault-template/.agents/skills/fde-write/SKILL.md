# 内容写作

<!-- FDE-OWNED-WORKFLOW: v1 -->

## 开始前

1. 从当前目录向上找到 `.fde/config.yaml`，按配置解析六类资产库。
2. 只读取本任务需要的文件，不跨知识库搜索。
3. 把库内事实、用户本轮信息、当前推断和未知项分开。
4. 原始材料不覆盖；删除、移动和批量写入先确认。

## 读取

- 选题记录
- 老板表达和禁区
- 产品事实
- 客户原话
- 案例和方法
- 目标平台

## 必须保留的能力

- 先诊断选题和材料缺口
- 支持公众号、小红书、搜索、朋友圈和口播
- 能生成实际草稿而不只给建议
- 使用老板原话、产品事实、客户原话和案例
- 成稿附来源和未核实项

## 执行

1. 确认平台、读者、目的和不能改的事实。
2. 建立材料表：要用的原话、数字、案例和观点。
3. 先给结构和缺口；缺口影响成稿时请求补充。
4. 按平台模式写草稿，末尾附来源清单和未核实项。

## 交付

- 写作合同
- 正文草稿
- 来源清单
- 未核实项
- 下一轮修改重点

每个关键判断附来源路径；没有来源的内容标为推断或待确认。

## 写回

- 草稿写入内容库的 `草稿`
- 用户确认后才进入 `待审核`
- 不覆盖原稿

## 停止条件

- 产品事实或案例结果无法核实时不用确定语气
- 未指定平台时不套平台格式
- 不编客户原话

## 接续

- 写完用 fde-review
- 只改开头用 fde-hook
- 公众号排版用 fde-format

来源沿革只用于追溯，不作为运行指令。需要追溯时读取 `references/source-map.md`。
