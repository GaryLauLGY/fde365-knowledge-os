# FDE365六类资产知识库规则

## 作用域

- 本文件约束当前 `FDE365知识库` 及其子目录。
- `.fde/config.yaml` 是六类资产、收件箱和运行目录的唯一路径真源。
- 旧 `.kb/` 只作历史追溯，不是运行配置或状态真源；任何 Agent 均不得按其中路径执行。
- 项目本地技能位于 `.agents/skills/`，只在当前知识库内使用。

## 六类资产

- `1-个人说明书`：身份、判断、表达和不能公开的边界。
- `2-产品库`：产品、价格、承诺、交付和异议。
- `3-客户需求库`：客户原话、行为、阶段和结果。
- `4-素材案例库`：事件、原话、数据、动作和结果。
- `5-方法论库`：实际使用过的方法、条件、步骤和失败信号。
- `6-内容生产`：选题、草稿、审核和发布；`已发布` 是流程终点，发布数据单独分析。

## 写入边界

- 录音、聊天、会议纪要、文档、图片和其他原始材料保留在 `0-待处理材料/待处理`；处理流程不会移动、删除或用摘要覆盖。只有用户在原始材料列表明确确认删除时，才将收件记录和对应原始文件一并移入回收站。
- 库内事实、用户本轮信息、AI 推断和未知项必须分开。
- 新增结论必须写明来源路径和日期；没有来源时标记为推断或待确认。
- 分类不确定时先留在待处理或待确认区，不强行写入正式资产。
- 移动、覆盖、删除和批量写入前必须展示预览并取得用户确认。
- 内容文件同时只处于一个阶段；目录和“当前阶段”字段必须一致。
- 阶段推进前必须由用户确认当前环节已经完成；不完整时先在同一对话调用对应内容技能。
- 发布数据由用户上传或回填，分析记录不得变成“已发布”之后的新阶段。
- 跨库关系只有在两端资产和来源能够支持时才建立；已确认关系写入两端 Markdown 的 `## 关联资产` 和完整路径 Wikilink，不以 Canvas 代替。
- 状态、索引、日志和版本只写入 `.fde`，AI 运行记录写入 `7-系统/AI协作`。
- 分流预览只显示在当前 Agent 对话和 AI 运行记录中，不得在待处理目录新建“分流预览”材料。

## AI 协作

- 不跨当前知识库检索，除非用户明确授权具体来源。
- 关键判断返回来源路径；来源冲突时不自动选边。
- 默认先诊断或生成预览，用户确认后再执行会改变现有资产的动作。
